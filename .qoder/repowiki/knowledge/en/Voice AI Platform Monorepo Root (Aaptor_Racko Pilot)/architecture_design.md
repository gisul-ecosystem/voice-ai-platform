Monorepo with a clear product/service boundary: `services/voice-agent/products/{interviewer,customer_support}` own product logic against a shared `voice_platform` runtime and `clients` provider layer; `packages/voice-ui` is a reusable npm workspace consumed by `apps/voice-frontend`. The root level holds cross-cutting artifacts only — `.github/workflows/ci.yml` defines the Dev CI/CD pipeline (Python + Node verify → Docker image build → self-hosted runner deploy), `deploy/` contains the staging Compose stack (`compose.staging.yml`, Caddyfile, `deploy.sh`) with immutable SHA-tagged images pushed to `ghcr.io/gisul-ecosystem`, `docs/` documents production architecture/SLOs/plans, `document/rules/project-conventions.mdc` is an always-applied LLM prompt encoding verified facts and code style rules, and `scripts/` holds ad-hoc E2E/load helpers. Dependency direction is one-way: products depend on shared platform/clients; nothing in this root scope depends on service internals.
